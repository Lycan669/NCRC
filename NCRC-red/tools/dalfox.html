Introduction

Qu'est-ce que dalfox ?

dalfox est un scanner XSS avancé, rapide et orienté paramètre. Il est particulièrement fort pour :

  • Détecter les XSS reflétées
  • Tester automatiquement beaucoup de payloads
  • Miner des paramètres intéressants
  • Travailler en pipeline avec gau, katana, waybackurls, gf...
  • Accélérer la chasse XSS en bug bounty / CTF
Quand l’utiliser ?
  • Après la recon (subfinder / httpx / katana / gau)
  • Quand tu as une liste d’URLs avec paramètres
  • Quand tu veux tester vite search, redirect, filter, q, id, page, callback...
  • Quand Nuclei n’a rien donné d’évident et que tu passes en phase manuelle assistée
Position dans ton arsenal : subfinder → httpx → katana/gau → dalfox → validation manuelle

Installation

Méthode recommandée (Go)

go install github.com/hahwul/dalfox/v2@latest

Vérifier l’installation

dalfox version

Outils complémentaires recommandés

go install github.com/lc/gau/v2/cmd/gau@latest
go install github.com/projectdiscovery/katana/cmd/katana@latest
go install github.com/tomnomnom/qsreplace@latest
go install github.com/tomnomnom/gf@latest
Conseil : dalfox devient beaucoup plus fort quand il est alimenté par de bonnes listes d’URLs (gau/katana) et un pré-filtre (`grep "="` / `gf xss`).

Concepts XSS utiles

Types de XSS à connaître
Type Description dalfox est fort ?
Reflected XSS Le payload revient dans la réponse immédiatement Oui, très fort
Stored XSS Le payload est stocké puis réaffiché plus tard Partiellement
DOM XSS Le problème vient du JavaScript côté client Moyen / selon options
Blind XSS L’exécution se voit ailleurs (admin panel, logs...) Oui avec callback `-b`
Paramètres souvent intéressants
  • q, search, query, s
  • redirect, url, next, return, callback
  • name, id, page, cat, filter
  • message, error, msg, text
Réflexe Jour J : priorise toujours les paramètres de recherche, redirection et affichage de messages.

Usage de base

1. Tester une URL unique
dalfox url "https://target.com/search?q=test"
2. Tester un fichier d’URLs
dalfox file urls.txt
3. Mode pipeline (le plus utile)
cat urls.txt | dalfox pipe
4. Mode silencieux + output
dalfox file urls.txt --silence -o xss-results.txt
5. Activer le mining de paramètres
dalfox file urls.txt --mining-dict --mining-dom

Flags importants (détaillés)

Flag Rôle Quand l’utiliser
url Scan d’une seule URL Test manuel rapide
file Scan d’un fichier Liste préparée
pipe Lit depuis stdin Pipelines bug bounty
--mining-dict Parameter mining via dictionnaire Quand tu veux découvrir plus de params
--mining-dom Cherche des params dans le DOM Pages JS riches
--deep-domxss Analyse DOM plus poussée Si tu suspectes du DOM XSS
-b Blind XSS callback/collaborator Forms, profils, tickets, feedback
-o Output file Toujours utile
--silence Moins de bruit Pendant les gros scans
-w Workers / parallélisme Pour accélérer
--skip-bav Skip certaines vérifs basiques Scan plus agressif / rapide
--waf-evasion Tentatives d’évasion WAF Si tu te fais bloquer
--custom-payload Payloads perso Quand tu as ta wordlist XSS

Exemples avancés

1. Scan standard d’une liste
dalfox file urls.txt --mining-dict --mining-dom -o dalfox.txt
2. Pipeline gau → dalfox
gau target.com | grep "=" | dalfox pipe --silence -o xss.txt
3. Pipeline katana → dalfox
katana -u https://target.com -silent | grep "=" | dalfox pipe
4. Avec gf xss
cat all-urls.txt | gf xss | dalfox pipe --silence -o gf-xss.txt
5. Mode plus agressif
dalfox file urls.txt --mining-dict --mining-dom --deep-domxss -w 20 --waf-evasion
6. Blind XSS (si tu as un callback)
dalfox url "https://target.com/contact?msg=test" -b https://TON-CALLBACK

Pipelines Bug Bounty

Pipeline XSS rapide (recommandé)
gau target.com | \
grep "=" | \
uro | \
dalfox pipe --mining-dict --silence -o xss-fast.txt
Pipeline recon complète → XSS
subfinder -d target.com -silent | \
httpx -silent | \
katana -silent | \
grep "=" | \
dalfox pipe -o xss.txt
Pipeline “qualité > quantité”
cat all-urls.txt | \
gf xss | \
qsreplace "FUZZ" | \
dalfox pipe --silence
Astuce : filtre d’abord les URLs. dalfox est puissant, mais il devient excellent quand tu lui donnes moins de bruit et de meilleurs candidats.

Plan Jour J (Hack ton lycée)

Méthode simple et efficace
  1. Recon : subfinder + httpx
  2. Auto vulns : nuclei (critical/high)
  3. Collecte d’URLs : gau / katana
  4. Filtre params : grep "=" ou gf xss
  5. XSS auto : dalfox
  6. Validation manuelle des vrais poplog / alert
Commandes prêtes pour le jour J
# 1) Live hosts
subfinder -d CIBLE -silent | httpx -silent -o live.txt

# 2) Nuclei fast
nuclei -l live.txt -severity critical,high -silent -o nuclei.txt

# 3) XSS candidates
gau CIBLE | grep "=" | tee xss-candidates.txt

# 4) dalfox
cat xss-candidates.txt | dalfox pipe --mining-dict --silence -o xss-found.txt
Priorité le jour J : ne perds pas 1h sur une XSS douteuse si Nuclei t’a déjà trouvé un panel exposé ou une CVE claire.

Tips Pro

1. Toujours pré-filtrer

Ne balance pas 50 000 URLs à dalfox sans filtre. Garde celles avec paramètres.

grep "=" urls.txt > params.txt
2. Vérifie toujours manuellement

Un finding dalfox n’est pas automatiquement un rapport validé. Ouvre l’URL, teste le payload, confirme le contexte.

3. Combine avec qsreplace
cat params.txt | qsreplace '">' | head
4. Si WAF devant
  • Baisse le parallélisme
  • Active --waf-evasion
  • Teste moins d’URLs mais plus intelligemment
Rappel légal : utilise dalfox uniquement sur les cibles autorisées du concours / programme.
