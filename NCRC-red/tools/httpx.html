Introduction

Qu'est-ce que httpx ?

httpx est un toolkit HTTP ultra-rapide développé par ProjectDiscovery. Il est devenu indispensable en bug bounty et en recon moderne.

Il permet de :

  • Prober rapidement des milliers d’hôtes
  • Récupérer le status code, le titre, la techno, les headers...
  • Détecter les technologies (tech-detect)
  • Suivre les redirections
  • Filtrer intelligemment les résultats
  • S’intégrer parfaitement dans des pipelines (subfinder → httpx → nuclei)
💡 Pourquoi httpx est si populaire ?
Très rapide, faible consommation mémoire, excellent en pipe avec d’autres outils ProjectDiscovery (subfinder, nuclei, katana...).

Installation

Méthode recommandée (Go)

go install -v github.com/projectdiscovery/httpx/cmd/httpx@latest

Avec pdtm (ProjectDiscovery Tool Manager)

pdtm -i httpx

Via apt (Kali)

sudo apt install httpx-toolkit
Note : Sur Kali le paquet s’appelle parfois httpx-toolkit pour éviter le conflit avec le module Python httpx.

Usage Basique

Prober une seule cible
httpx -u https://target.com
Prober une liste de domaines
httpx -l domains.txt
Lire depuis stdin (très courant)
cat domains.txt | httpx
Afficher plus d’informations
httpx -l domains.txt -title -tech-detect -status-code -web-server

Flags les plus utiles

Flag Description
-uCible unique
-lFichier de cibles
-titleAffiche le titre de la page
-status-codeAffiche le code HTTP
-tech-detectDétecte les technologies
-web-serverAffiche le serveur web
-content-lengthAffiche la taille de la réponse
-follow-redirectsSuit les redirections
-follow-host-redirectsSuit les redirections du même host
-mcMatch status codes (ex: 200,301,302)
-fcFilter status codes
-tNombre de threads
-timeoutTimeout (secondes)
-retriesNombre de retries
-silentMode silencieux (seulement les résultats)
-oFichier de sortie
-jsonSortie en JSON
-cdnAffiche les informations CDN
-probeForce le probe même sur les non-HTTP
-portsPorts à scanner (ex: 80,443,8080)
-pathChemin à ajouter (ex: /admin)
-http2Force HTTP/2
-no-colorDésactive les couleurs

Exemples Détaillés

1. Scan basique + titre + status + techno
httpx -l domains.txt -title -status-code -tech-detect -web-server
2. Seulement les hosts qui répondent 200
httpx -l domains.txt -mc 200 -silent
3. Suivre les redirections + afficher le titre final
httpx -l domains.txt -follow-redirects -title -status-code
4. Scanner plusieurs ports
httpx -l ips.txt -ports 80,443,8080,8443,8000 -title
5. Ajouter un chemin spécifique
httpx -l domains.txt -path /admin -mc 200,301,302,403
6. Sortie JSON propre
httpx -l domains.txt -title -tech-detect -json -o results.json
7. Filtrer les CDN (Cloudflare, Akamai...)
httpx -l domains.txt -cdn

Pipelines Bug Bounty

httpx brille particulièrement dans les chaînes d’outils.

Pipeline classique Subdomain → httpx
subfinder -d target.com -silent | httpx -silent -title -status-code -tech-detect
Subfinder → httpx → nuclei
subfinder -d target.com -silent | httpx -silent | nuclei -t cves/ -silent
Récupérer uniquement les hosts vivants
cat all-subs.txt | httpx -silent > live-hosts.txt
Pipeline avec Katana + httpx
katana -u https://target.com -silent | httpx -silent -title -mc 200
Filtrer les applications intéressantes
cat domains.txt | httpx -title -tech-detect -status-code | grep -i "wordpress\|laravel\|django\|admin"

Tips Pro

1. Mode silencieux + threads élevés
httpx -l domains.txt -silent -t 100
2. Détecter les technologies + sauvegarder
httpx -l domains.txt -tech-detect -title -status-code -o tech-results.txt
3. Scanner rapidement + suivre les redirections
httpx -l domains.txt -follow-redirects -title -mc 200,301,302
4. Utiliser avec une wordlist de chemins
httpx -l domains.txt -path /robots.txt,/sitemap.xml,/admin -mc 200
Astuce Bug Bounty : Combine toujours subfinder → httpx → nuclei. C’est l’un des pipelines les plus efficaces actuellement.
Rappel : Utilise httpx uniquement sur des cibles autorisées.
