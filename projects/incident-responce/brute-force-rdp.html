🔴 RDP Brute Force Attack

Real-world incident response guide for detecting and containing RDP brute force attacks.

⚠️ CRITICAL SEVERITY
MTTD 15-30 min
MTTR 1-2 hours
Risk Level CRITICAL
Detection Type Log Based

📋 Executive Summary

RDP brute force attacks are one of the most common attack vectors targeting Windows environments. Attackers systematically attempt to guess credentials using automated tools, often targeting RDP port 3389. Once successful, they gain remote access and can move laterally within your network, deploy ransomware, or exfiltrate data.

🎯 Attack Overview

🌐 Primary Target Windows RDP (Port 3389)
⏱️ Attack Duration Hours to Days
🛡️ Impact Level System Compromise
👤 Success Indicator Successful Login

🔍 Phase 1: Detection

Identify RDP brute force attempts before successful compromise.

Splunk Query - Detect Failed RDP Attempts

Failed RDP Login Attempts (4625) SPL 
sourcetype="WinEventLog:Security" EventCode=4625 
  [DestinationPort=3389 OR dest_port=3389]
| stats count as failed_attempts by src_ip, dest
| where failed_attempts > 5
| table src_ip, dest, failed_attempts
| sort - failed_attempts
🔎 What This Does:
  • Searches Windows Security Event Log (EventCode 4625 = failed login)
  • Filters for RDP traffic (port 3389)
  • Groups by source IP and destination
  • Alerts if > 5 failed attempts from same IP
  • Sorts by highest attempt count
Brute Force Detection (Time-based) SPL Advanced 
sourcetype="WinEventLog:Security" EventCode=4625
  (DestinationPort=3389 OR dest_port=3389)
| bucket _time span=5m
| stats count as attempts by src_ip, _time
| where attempts > 10
| eval time_window="5min"
| eval risk_score = attempts * 2
| where risk_score > 20
| table src_ip, _time, attempts, risk_score, time_window
🔎 Advanced Detection:
  • Buckets events into 5-minute windows
  • Detects 10+ failures per IP in 5 minutes
  • Calculates risk score
  • Triggers alert when risk > 20
  • Perfect for automated response
Successful Login After Failed Attempts SPL Correlation 
sourcetype="WinEventLog:Security" 
  (EventCode=4625 OR EventCode=4624)
  DestinationPort=3389
| stats 
    count(eval(EventCode=4625)) as failed_logins,
    count(eval(EventCode=4624)) as successful_logins,
    values(user) as users
    by src_ip, dest
| where failed_logins > 10 AND successful_logins >= 1
| table src_ip, dest, failed_logins, successful_logins, users
| eval severity="CRITICAL"
🎯 Critical Indicator:
  • Correlates failed AND successful logins
  • Shows attacker broke through
  • Immediate incident escalation needed
  • Marks as CRITICAL severity
  • Shows compromised user accounts

KQL Query - Azure Sentinel Detection

RDP Brute Force Detection KQL 
SecurityEvent
| where EventID == 4625
| where LogonType == 10  // RDP/RemoteInteractive
| summarize 
    FailedAttempts = count(),
    FirstAttempt = min(TimeGenerated),
    LastAttempt = max(TimeGenerated)
    by SourceIpAddr, Computer, Account
| where FailedAttempts > 15
| extend 
    Duration = LastAttempt - FirstAttempt,
    AttacksPerMinute = (FailedAttempts / (Duration / 1m))
| where AttacksPerMinute > 3
| project SourceIpAddr, Computer, Account, FailedAttempts, AttacksPerMinute
🔎 Azure Sentinel Logic:
  • Monitors SecurityEvent table
  • Filters for failed logins (4625)
  • Identifies RDP sessions (LogonType=10)
  • Calculates attacks per minute
  • Alerts on high velocity attacks
Suspicious RDP Logon Success KQL 
SecurityEvent
| where EventID == 4624
| where LogonType == 10
| join kind=innerunique (
    SecurityEvent
    | where EventID == 4625
    | where LogonType == 10
    | summarize FailedAttempts = count() by SourceIpAddr
) on SourceIpAddr
| where FailedAttempts > 10
| extend 
    Severity = "HIGH",
    ThreatLevel = "COMPROMISED"
| project TimeGenerated, SourceIpAddr, Account, Computer, FailedAttempts, Severity
🎯 Correlation Query:
  • Joins failed attempts with successful login
  • Shows brute force success
  • Marks account as potentially compromised
  • High priority incident

SIGMA Rule - Detection as Code

RDP Brute Force - SIGMA Format SIGMA YAML 
title: RDP Brute Force Attack Detection
id: rdp-brute-force-001
description: Detects multiple failed RDP login attempts from single IP
status: experimental
author: NCRC Security Team
date: 2026/09/20

logsource:
  product: windows
  service: security
  definition: Windows Security Event Log

detection:
  selection:
    EventID: 4625
    LogonType: 10
    DestinationPort: 3389
  
  timeframe: 5m
  condition: selection | count(SourceIp) by SourceIp > 10

falsepositives:
  - Legitimate password managers
  - User testing authentication
  - Misconfigured applications

level: high
📋 SIGMA Rule Details:
  • Portable detection rule format
  • Works across multiple SIEM platforms
  • Detects 10+ failed attempts per IP in 5 minutes
  • Includes false positive mitigations
  • Can be auto-converted to SPL, KQL, etc.

🐧 Linux Commands for Log Analysis

Parse Windows Event Logs on Linux Bash 
# Extract failed RDP attempts from Windows Security log
grep -i "failed\|4625" /path/to/security.evtx | \
  grep -i "3389\|rdp" | \
  awk '{print $NF}' | \
  sort | uniq -c | sort -rn

# Count failed login attempts per IP (from Syslog)
cat /var/log/auth.log | \
  grep "Failed password" | \
  awk '{print $(NF-3)}' | \
  sort | uniq -c | \
  awk '$1 > 5 {print $2, $1 " attempts"}'

# Real-time RDP monitoring with tail
tail -f /var/log/auth.log | \
  grep --line-buffered "Failed password" | \
  grep --line-buffered "port 3389"
📊 Log Analysis Commands:
  • Extract failed login events
  • Count attempts per IP address
  • Filter RDP-specific traffic
  • Real-time monitoring capability
  • Useful for correlation analysis
Network Traffic Analysis Bash + tcpdump 
# Capture RDP traffic on port 3389
sudo tcpdump -i any -n port 3389 -w rdp_traffic.pcap

# Analyze captured packets
tcpdump -r rdp_traffic.pcap | \
  grep "Flags\|RST\|SYN" | \
  awk '{print $3}' | \
  cut -d'.' -f1-4 | \
  sort | uniq -c | sort -rn

# Check for brute force pattern (multiple retransmissions)
tcpdump -r rdp_traffic.pcap -n | \
  grep "retransmission" | \
  wc -l
🌐 Network Detection:
  • Captures RDP protocol traffic
  • Analyzes connection patterns
  • Detects rapid reconnect attempts
  • Network-level evidence
  • Complements log-based detection

🔬 Phase 2: Investigation & Analysis

Deep dive into the attack to understand scope and impact.

📊

1. Identify Attack Source

Objective: Determine attacker IP and origin

# Check for brute force source IPs
netstat -an | grep 3389 | grep ESTABLISHED
ss -tan | grep :3389

# Analyze source IP geolocation
whois [SOURCE_IP]
geoiplookup [SOURCE_IP]
🎯

2. Identify Target Accounts

Objective: Which accounts were targeted?

# List failed login attempts per user
grep EventCode=4625 security.log | \
  grep 3389 | \
  awk '{print $USERNAME}' | \
  sort | uniq -c | sort -rn

# Check for successful breach
grep EventCode=4624 security.log | \
  grep 3389 | awk '{print $USERNAME}'
⏱️

3. Timeline Analysis

Objective: When did attack occur?

# Extract timestamps of failed attempts
grep EventCode=4625 security.log | \
  grep 3389 | \
  awk '{print $1, $2}' | \
  sort | uniq -c | sort -k3

# Find first and last attempt
head -n 1 events.log  # First attempt
tail -n 1 events.log  # Last attempt
🚀

4. Post-Compromise Activity

Objective: What happened after login?

# Check for lateral movement (4624 logins)
grep EventCode=4624 security.log | \
  grep "[COMPROMISED_USER]" | \
  awk '{print $SOURCE_IP}' | sort | uniq

# Check for logon type after successful RDP
grep -A 5 "EventCode=4624" security.log | \
  grep LogonType
🛠️

5. Privilege Escalation Check

Objective: Did they escalate privileges?

# Check for privilege escalation attempts
grep -i "privilege\|admin\|4688" security.log | \
  grep "[COMPROMISED_USER]"

# Look for UAC bypass attempts
grep "User Account Control" security.log | \
  grep -i "denied\|blocked"
🔍

6. Persistence Mechanisms

Objective: Did they install backdoors?

# Check for suspicious scheduled tasks
tasklist /svc | grep -i "suspicious"

# Look for new user accounts
net user | grep -v "Administrator\|Guest"

# Check for SSH keys or backdoors
ls -la ~/.ssh/
find /root -name "authorized_keys"

🔐 Phase 3: Containment & Isolation

Stop the attack and prevent further damage.

IMMEDIATE

Step 1: Block Attacker IP

Prevent continued attack attempts

# Windows Firewall
netsh advfirewall firewall add rule \
  name="Block RDP Brute Force" \
  dir=in action=block remoteip=[ATTACKER_IP] \
  protocol=tcp localport=3389

# Linux iptables
sudo iptables -A INPUT -s [ATTACKER_IP] -j DROP
sudo iptables-save > /etc/iptables/rules.v4

# Cloud (AWS Security Group)
aws ec2 revoke-security-group-ingress \
  --group-id sg-xxxxx \
  --protocol tcp --port 3389 \
  --cidr [ATTACKER_IP]/32
IMMEDIATE

Step 2: Disable Compromised Account

Prevent attacker from using stolen credentials

# Disable user account immediately
net user [USERNAME] /active:no

# Force password reset
net user [USERNAME] *

# Revoke RDP access
net localgroup "Remote Desktop Users" [USERNAME] /delete

# Check Active Directory (if on domain)
Get-ADUser -Identity [USERNAME] | Disable-ADAccount
IMMEDIATE

Step 3: Kill Active Sessions

Terminate attacker's remote session

# List all RDP sessions
query session

# Kill specific session
logoff [SESSION_ID]

# Disconnect all sessions for user
query session | grep [USERNAME] | \
  awk '{print $2}' | xargs -I {} logoff {}

# Force disconnect from PowerShell
Get-PSSession | Stop-PSSession
URGENT

Step 4: Isolate Affected Server

Network segmentation to prevent lateral movement

# Disable network interfaces temporarily
sudo ifconfig eth0 down

# Or use VLAN isolation (if infrastructure allows)
# Alternatively, snapshot VM state BEFORE isolation
# for forensic analysis

# Document current state for investigation
systemctl status --no-pager > /tmp/system_state.txt
netstat -tan > /tmp/network_state.txt
URGENT

Step 5: Change RDP Port (Temporary)

Make target less attractive while maintaining access

# Registry modification (Windows)
reg add "HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp" \
  /v PortNumber /t REG_DWORD /d 13389 /f

# Restart RDP service
net stop TermService
net start TermService

# Update firewall rules
netsh advfirewall firewall add rule \
  name="RDP Alternative Port" dir=in action=allow \
  protocol=tcp localport=13389
URGENT

Step 6: Enable Account Lockout

Prevent future brute force attacks

# Set account lockout policy
net accounts /lockoutthreshold:5 /lockoutduration:30 /lockoutwindow:5

# Or via Group Policy
gpresult /h policy_report.html

# For Active Directory
Set-ADAccountLockoutPolicy -Identity "AD:\CN=Default Password Policy" \
  -LockoutThreshold 5 -LockoutDuration 00:30:00

🧹 Phase 4: Eradication

Remove all traces of the attack and attacker access.

🔍 Scan for Backdoors

# Search for suspicious processes
Get-Process | where {$_.Path -notmatch "System32|Program Files"}

# Check for hidden user accounts
net user | findstr /i "hidden"
wmic useraccount get name,disabled,status

# Look for startup items
Get-CimInstance Win32_StartupCommand | 
  Select-Object Name, Command

🗂️ Clean Logs

# Backup logs FIRST for investigation
cp /var/log/auth.log /evidence/auth.log.backup

# Clear failed login attempts (careful!)
wevtutil cl Security

# Clear RDP specific logs
logman stop "RDP" -ets
wevtutil cl Microsoft-Windows-TerminalServices-LocalSessionManager/Operational

🛡️ Remove Persistence

# Delete scheduled tasks
taskkill /IM [SUSPICIOUS_TASK.EXE] /F
schtasks /delete /tn "[SUSPICIOUS_TASK]" /f

# Remove startup entries
reg delete "HKLM\Software\Microsoft\Windows\Run" \
  /v [SUSPICIOUS_KEY] /f

# Check and remove SSH keys
rm -f ~/.ssh/authorized_keys
rm -f /root/.ssh/authorized_keys

🔄 Patch & Update

# Windows Update
wuauclt.exe /updatenow
Get-WindowsUpdate -Install -AcceptAll -AutoReboot

# Linux Updates
apt update && apt upgrade -y
yum update -y

# Check for RDP vulnerability patches
systeminfo | findstr /C:"OS Version"

🔐 Reset Credentials

# Reset all potentially compromised passwords
# Force password expiration
net user [USERNAME] /expires:today

# Reset service account passwords
Get-ADUser -Filter {ServicePrincipalName -ne "$null"} | 
  Set-ADAccountPassword -NewPassword (Read-Host "New Password")

✅ Verification

# Verify RDP is clean
Get-Service TermService | select Status
netstat -an | grep 3389

# Check for attacker artifacts
Get-ChildItem -Path C:\ -Attributes Hidden -Recurse
find / -name ".*" -type f 2>/dev/null

🎯 Indicators of Compromise (IoCs)

Evidence that confirms RDP brute force attack occurred.

📋 Log-Based IoCs

  • Event ID: 4625 (Failed Login)
  • Event ID: 4624 (Successful Login)
  • LogonType: 10 (RDP)
  • Port: 3389 (RDP Default)
  • Source: Unusual geography
  • Timeframe: Off-hours login

🌐 Network-Based IoCs

  • Source IP: Attacker IP address
  • Destination Port: 3389
  • Traffic Pattern: Rapid connections
  • Geolocation: Non-business region
  • Protocol: RDP/TLS
  • Bandwidth: Unusual data transfer

💻 System-Based IoCs

  • New User Accounts: Suspicious accounts
  • Scheduled Tasks: Hidden/suspicious tasks
  • Registry Changes: Persistence mechanisms
  • File Artifacts: Attacker tools
  • Process Behavior: Unusual execution
  • Network Connections: C2 callbacks
